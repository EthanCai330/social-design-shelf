# 下拉展开摘要 Pull-To-Expand Summary

- **风格**：玻璃拟态 / 静谧极简
- **来源**：用户提供的提示词 · 收录于 2026-11-25
- **适用场景**：首页概览、账户余额、仪表盘

## 行为
页面顶部一条显示关键数字的小胶囊。只有在胶囊上往下拉时，它才跟随手指逐渐展开成完整统计面板，下方内容同步被推下并轻微变暗；往上推收回。在页面其他位置下拉仍然是下拉刷新。

## 时长与曲线
- 跟手：**1:1 跟随手指位移**（不加任何系数），由手指 Y 差实时驱动
- 松手吸附：spring，`stiffness 300 / damping 30 / mass 1`（ζ≈0.87，基本无过冲）
- 内容变暗：与展开比例同步，0 → 12%

**关于阻尼**：早期版本写"1:1 跟手并带 0.85 阻尼"，这两句互相矛盾。
本条目定死为 **1:1 跟手**；手感偏硬的问题靠"松手吸附"和"过度拖动的橡皮筋"解决，不靠全局系数。
若要减弱跟手感，应显式写成"跟手系数 0.85"并从数值上说明，不要同时声称 1:1。

## 视觉
- 胶囊：高 `36px`，宽 `100% - 36px`（左右各 18px 边距）
- 胶囊静态圆角：`18px`（= 高度的一半，即全圆角胶囊；**不要写 999px**，见下）
- 展开面板圆角：`24px`
- 毛玻璃 `blur(16px)` + 白 80% + `box-shadow: 0 1px 3px rgba(0,0,0,.06), inset 0 0 0 1px rgba(0,0,0,.04)`
  （必须带描边或阴影，否则白 80% 在浅色背景上边缘会消失）

## 圆角插值（这里是最容易写错的地方）
**不要写 `border-radius: 999px → 24px`。** 36px 高的元素设 `999px` 时，浏览器实际渲染半径
被 clamp 到半高（18px）。若代码真把 999 线性插值到 24，前约 97% 的行程里半径都大于半高、
视觉上完全卡死不动，最后几毫秒才突然跳变成 24px——效果是坏的。

正确做法：**从 18px 插值到 24px**。
```
radius = 18 + (24 - 18) * progress    // progress = (height - 36) / (FULL - 36)
```
面板展开到足够高（≥48px）之后，`24px` 才真正生效。

## 尺寸与阈值
- 展开总高 `FULL = 260px`（在实现中可自适应，min(260, 容器高 - 40)）
- 吸附阈值：超过 `FULL - 36` 的 40% 判定展开
- 橡皮筋：下拉超过 `FULL` 后 `offset = FULL + (d - FULL) * 0.3`

## 降级
`prefers-reduced-motion`：松手后直接吸附到终态，无 spring。
无障碍：胶囊必须是可聚焦按钮，Enter 也能展开；不能让手势成为唯一入口。

## 细节与反例
- **手势区域必须严格限定在胶囊内**：这是整个设计的关键约束，否则与下拉刷新冲突。
- 跟手必须真正 1:1（见上），系数和"1:1"不能同时出现。
- 页面其他位置下拉必须完全不拦截，交给下拉刷新。
- 内层可滚动的明细面板要处理嵌套滚动冲突（`overscroll-behavior: contain`）。
- **不要写"或保持不动由明细补充"这类二选一**——规格必须唯一，否则复刻结果不可控。
  本条目定为：**数字保持不动**，展开后在下方补充明细行。
